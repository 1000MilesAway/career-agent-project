# Пробник career-agent

Проверка идеи до продукта: честно ли модель оценивает вакансии и сколько стоит один
пользователь. Кода продукта здесь нет — это стенд, который потом выбрасывается,
кроме промптов (`prompts.py`), они переезжают в сервис.

## Запуск

Ключ DeepSeek — в `.env` в корне (`DEEPSEEK_API_KEY`).

```bash
# одна вакансия, все четыре шага
.venv/bin/python -m probe.run one --resume data/resumes/my.pdf --vacancy data/vacancies/v1.txt

# пакетный прогон: одно резюме против папки вакансий — главный сценарий замера
.venv/bin/python -m probe.run batch --resume data/resumes/my.pdf --vacancies data/vacancies --steps evaluate

# сколько потрачено суммарно
.venv/bin/python -m probe.run cost

# одна вакансия по ссылке на Хабр Карьеру
.venv/bin/python -m probe.run url --resume data/resumes/cv.md \
    --url https://career.habr.com/vacancies/1000168402

# сканер как в career-ops: фильтры до модели (основной способ)
.venv/bin/python -m probe.run scan2 --resume data/resumes/cv.md \
    --remote --pages 2 --limit 8 --show-dropped

# старый сканер: поиск одним запросом, оценка всего подряд (дороже)
.venv/bin/python -m probe.run scan --resume data/resumes/cv.md \
    --query python --remote --limit 10

# вакансии из Telegram-каналов: сбор и фильтры, модель не вызывается
.venv/bin/python -m probe.run tg --show-dropped

# веб-экран: резюме + подбор вакансий по Хабру
.venv/bin/python -m probe.web    # http://127.0.0.1:8010

# то же, с перезапуском на любую правку .py — для работы над кодом
PROBE_RELOAD=1 .venv/bin/python -m probe.web
```

Параметры сканера: `--query` запрос, `--remote` только удалёнка, `--salary` вилка от,
`--pages` страниц выдачи (25 вакансий на странице), `--limit` сколько оценить,
`--min-score` показывать только вакансии не ниже балла.

## Как устроен `scan2`

Повторяет схему career-ops: дорогая модель включается последней.

1. **Сбор** — публичный JSON API Хабра, несколько запросов, повторы по id убираются.
   Бесплатно. API сразу отдаёт грейд, удалёнку, зарплату, навыки, специализацию.
2. **Фильтры** — стоп-слова в заголовке, специализация, ключевые слова, грейд,
   удалёнка, вилка. Бесплатно. Здесь отсеивается большая часть выдачи.
3. **История** — что показывали в прошлый раз, второй раз не оценивается
   (`out/scan-history.tsv`).
4. **Оценка** — только выжившие идут в модель.

Профиль поиска (запросы, ключевые слова, стоп-слова, минимальный грейд) модель
**предлагает** по резюме — и ничего не пишет, пока вы не согласитесь. CLI показывает
дифф и спрашивает `[y/N]`; `--yes` принимает без вопроса (для неинтерактивных
прогонов). Без ответа и без `--yes` предложение отклоняется, а не принимается молча.
Само предложение паркуется в `out/search-profile.proposal.json` — его можно открыть
и прочитать глазами.

Принятый профиль сохраняется в `out/search-profile.json`. Файл можно править
руками: при следующем запуске берётся он. `--regenerate` пересобирает,
`--starter` берёт готовый шаблон из `probe/defaults.py` вместо генерации.

В вебе то же самое: подбор до решения идёт по стартовому шаблону, предложение
показывается таблицей изменений с кнопками «Принять» и «Отклонить». Поля, которых
предложение не касается, не затираются.

## Правки не видны в браузере

`index.html` читается на каждый запрос — правку разметки и скриптов достаточно
обновить в браузере (Ctrl+Shift+R, если вмешался кеш).

**Правка `.py` требует перезапуска сервера.** Процесс держит код в памяти:
пока он жив, новые эндпоинты не появятся, сколько ни обновляй страницу.
Либо перезапустить руками, либо запускать с `PROBE_RELOAD=1` — тогда uvicorn
поднимается сам на каждое изменение файла.

Признак, что вы смотрите на старый процесс: `ps aux | grep probe.web` показывает
дату запуска раньше ваших правок.

## Веб: три страницы, полный пайплайн без авторизации

Этапы разнесены по страницам, входа не требуется:

| Страница | Что там |
|---|---|
| **Моё резюме** | загрузка, разобранный профиль, списки профиля поиска |
| **Поиск** | подбор, бесплатный отсев, triage, оценка, кнопка «В избранное» |
| **Избранное** | материалы к отклику и статусы трекера |

Текущая страница держится в хеше адреса. «Очистить» на странице поиска
**не трогает избранное**: там лежат оплаченные отчёты.

Сценарий сверху вниз:

1. **Резюме** — загрузка и разбор в профиль.
2. **Подбор** — Хабр Карьера (запросы из профиля поиска) и кнопка «Telegram-каналы».
   Оба источника кладут найденное в один список.
3. **Бесплатный отсев** — стоп-слова, специализация, грейд, вилка. Причины показаны.
4. **Отсеять моделью** — triage одним дешёвым вызовом на всю пачку.
5. **Оценить** — полный отчёт по вакансии.
6. **В избранное** — отложить вакансию, с которой стоит работать.
7. **Сопровод / Резюме / Интервью** (на странице избранного) — три кнопки,
   каждая готовит один документ и стоит отдельно (0.23 / 0.24 / 0.17 ₽).
   Купленный помечается галочкой: повторный показ бесплатный.
8. **Трекер** (там же) — откликнулся → ответили → интервью → оффер / отказ /
   отложено. Переходы пишутся в лог.

Материалы готовятся **поверх готового отчёта**: он вход для всех трёх шагов,
поэтому повторно не покупается. Кнопки появляются только у оценённой вакансии.

Сводка расходов под списком считает по найденному, а не по файлам прогонов
(этим занимается `probe.run cost`).

Вкладки «Ссылка или текст» и «Поиск по Хабр Карьере» убраны: порядок «фильтры
до модели» уже выбран, а выбор сканера только путал демонстрацию.

Между перезагрузками страницы и перезапусками сервера сохраняется:

| Файл | Что там |
|---|---|
| `out/found.json` | накопительный список найденного с баллами, отчётами, материалами и статусами |
| `out/resume-state.json` | разобранное резюме и принятый профиль поиска |

**У Telegram-вакансии текст поста хранится в самой строке.** У `t.me` нет страницы,
которую можно дочитать по ссылке, поэтому оценка и материалы читают текст, собранный
на этапе скана. При повторном скане этот текст намеренно не обновляется: дедуп
в Telegram идёт по тексту, значит другой текст — это другая вакансия.

Найденное копится: новый подбор дописывает вакансии к списку, слияние идёт
по id. Повторный скан обновит зарплату и грейд, но **не тронет** уже оплаченный
балл — кнопка «Отчёт» у оценённой вакансии показывает сохранённый отчёт бесплатно.
Чистится только кнопкой «Очистить».

Стартовый шаблон — часть продукта, а не работа пользователя: в career-ops так же,
там списки лежат в `templates/portals.example.yml` и копируются при установке.

Про `word:` в списках слов: короткие слова прячутся внутри длинных. Без границ
«QA» отсекает «Quality», а «Go» — «Google». Слова до 3 букв получают границы
автоматически, для остальных ставьте префикс `word:`.

## Источники вакансий

Сейчас поддержан **career.habr.com**: ссылка на вакансию и поиск по каталогу.
HTML отдаётся сервером, JavaScript не нужен, блокировок с сервера нет.
`robots.txt` Хабра разрешает `/vacancies` и запрещает `/responses` и личные разделы —
мы читаем только публичные страницы и ничего не отправляем от имени пользователя.
Между запросами пауза 1 секунда.

Ссылки на hh.ru не поддержаны намеренно: с сервера отдаётся 403, см. `docs/01-market.md`.
Для них по-прежнему текст или скриншот.


## Источник Telegram (`tg`)

Каналы читаются через публичное веб-превью `t.me/s/<канал>`: обычный GET, без
ключей, без Bot API и без юзербота. Bot API так не умеет (нужны права админа
в канале, истории нет), а юзербот — это личный аккаунт под риском бана ради
данных, которые и так открыты.

**Групп это не касается.** У чатов превью нет в принципе: `t.me/s/<имя>` отвечает
302, и это не блокировка, а отсутствие функции. Отличить можно по `t.me/<имя>`:
`members` — чат (недоступен), `subscribers` — канал. Крупные чаты с вакансиями
поэтому мимо; они перечислены в `chats_unreachable`, чтобы не проверять их заново.

Сложность не в доступе, а в структуре: у Хабра есть поля (заголовок, грейд,
специализация, вилка), у поста — только плоский текст. Поэтому перед обычными
фильтрами добавлена бесплатная ступень `looks_like_vacancy()`:

- короткие посты — оффтоп («Сегодня День программиста» проходил все фильтры
  по ключевым словам);
- резюме соискателей (`#cv`, `#opentowork`, «ищу работу») — половина некоторых
  каналов, и они не должны попадать в отчёт как вакансии;
- реклама курсов и вебинаров;
- вакансии без контакта для отклика.

Вилка **не требуется**: в Telegram её указывают редко, и обязательное условие
выбрасывало две трети настоящих вакансий.

Заголовком считается первая строка без хэштегов. У семейства `runello_rus_*`
дополнительно читаются поля `Грейд:` и `Стек:` — единственная настоящая структура,
которая в Telegram встречается.

Канал, молчащий дольше 30 дней, пропускается: `t.me/s/` всегда отдаёт последнюю
страницу, поэтому мёртвый канал отвечает `200` и двадцатью постами и выглядит
здоровым (`golangjob` бодро отдаёт февраль 2023). Дедуп идёт **по тексту**, а не
по id: каналы переносят одну вакансию новыми постами.

Список каналов — `data/sources/telegram-channels.json`: `core` (берётся по
умолчанию), `adjacent` (другие стеки, по `--groups core,adjacent`), `special`
(с оговорками) и `rejected` с причиной отсева. Список — данные, а не код: каналы
умирают тихо, и обновление списка не должно означать правку модуля.

## Режимы прогона

`--steps` выбирает именованный режим, а не набор галочек. Цены и время — из
замера недели 0 (`docs/decisions.md`), они же показываются в вебе до запуска.

| Режим | Шаги | Цена | Время |
|---|---|---|---|
| `evaluate` | оценка | 0.17 ₽ | 13 с |
| `apply` | оценка + резюме + письмо | 0.64 ₽ | 40 с |
| `all` | плюс подготовка к интервью | 0.81 ₽ | 54 с |

Неизвестное имя режима падает на `evaluate`: опечатка не должна запускать
полный пакет. Режимы описаны в `probe/profiles.py` — в продукт переезжают оттуда.

Отдельно от режима: `--model deepseek-v4-pro` — сравнить Flash с сильной моделью.

## Куда класть данные

- `data/resumes/` — PDF, DOCX или TXT резюме.
- `data/vacancies/` — тексты вакансий, по файлу на вакансию.

Обе папки и `out/` в `.gitignore`: это персональные данные, в репозиторий не идут.
Резюме и вакансии для прогона держите в разных папках, иначе резюме попадёт
в пакетный прогон как вакансия.

## Что смотреть в результатах

1. **Разброс баллов.** Если все оценки в пределах 1.0 — промпт врёт и льстит.
   Сводка сама предупредит об этом.
2. **Evidence в требованиях.** Должны быть ссылки на конкретный опыт, не общие слова.
3. **Выдумки.** В `changes` тейлоринга и в STAR-историях не должно появляться
   опыта, которого нет в резюме. Это главный риск продукта.
4. **Цена и время** — в конце каждого прогона.
