# Пробник career-agent

Проверка идеи до продукта: честно ли модель оценивает вакансии и сколько стоит один
пользователь. Кода продукта здесь нет — это стенд, который потом выбрасывается,
кроме промптов (`prompts.py`), они переезжают в сервис.

## Запуск

Ключ DeepSeek — в `.env` в корне (`DEEPSEEK_API_KEY`).

```bash
# одна вакансия, все четыре шага
.venv/bin/python -m probe.run one --resume data/resumes/my.pdf --vacancy data/vacancies/v1.txt

# пакетный прогон: одно резюме против папки вакансий — главный сценарий замера
.venv/bin/python -m probe.run batch --resume data/resumes/my.pdf --vacancies data/vacancies --steps evaluate

# сколько потрачено суммарно
.venv/bin/python -m probe.run cost

# одна вакансия по ссылке на Хабр Карьеру
.venv/bin/python -m probe.run url --resume data/resumes/cv.md \
    --url https://career.habr.com/vacancies/1000168402

# сканер как в career-ops: фильтры до модели (основной способ)
.venv/bin/python -m probe.run scan2 --resume data/resumes/cv.md \
    --remote --pages 2 --limit 8 --show-dropped

# старый сканер: поиск одним запросом, оценка всего подряд (дороже)
.venv/bin/python -m probe.run scan --resume data/resumes/cv.md \
    --query python --remote --limit 10

# веб-экран: резюме, ссылка или текст, поиск по Хабру
.venv/bin/python -m probe.web    # http://127.0.0.1:8010
```

Параметры сканера: `--query` запрос, `--remote` только удалёнка, `--salary` вилка от,
`--pages` страниц выдачи (25 вакансий на странице), `--limit` сколько оценить,
`--min-score` показывать только вакансии не ниже балла.

## Как устроен `scan2`

Повторяет схему career-ops: дорогая модель включается последней.

1. **Сбор** — публичный JSON API Хабра, несколько запросов, повторы по id убираются.
   Бесплатно. API сразу отдаёт грейд, удалёнку, зарплату, навыки, специализацию.
2. **Фильтры** — стоп-слова в заголовке, специализация, ключевые слова, грейд,
   удалёнка, вилка. Бесплатно. Здесь отсеивается большая часть выдачи.
3. **История** — что показывали в прошлый раз, второй раз не оценивается
   (`out/scan-history.tsv`).
4. **Оценка** — только выжившие идут в модель.

Профиль поиска (запросы, ключевые слова, стоп-слова, минимальный грейд) модель
**предлагает** по резюме — и ничего не пишет, пока вы не согласитесь. CLI показывает
дифф и спрашивает `[y/N]`; `--yes` принимает без вопроса (для неинтерактивных
прогонов). Без ответа и без `--yes` предложение отклоняется, а не принимается молча.
Само предложение паркуется в `out/search-profile.proposal.json` — его можно открыть
и прочитать глазами.

Принятый профиль сохраняется в `out/search-profile.json`. Файл можно править
руками: при следующем запуске берётся он. `--regenerate` пересобирает,
`--starter` берёт готовый шаблон из `probe/defaults.py` вместо генерации.

В вебе то же самое: подбор до решения идёт по стартовому шаблону, предложение
показывается таблицей изменений с кнопками «Принять» и «Отклонить». Поля, которых
предложение не касается, не затираются.

Стартовый шаблон — часть продукта, а не работа пользователя: в career-ops так же,
там списки лежат в `templates/portals.example.yml` и копируются при установке.

Про `word:` в списках слов: короткие слова прячутся внутри длинных. Без границ
«QA» отсекает «Quality», а «Go» — «Google». Слова до 3 букв получают границы
автоматически, для остальных ставьте префикс `word:`.

## Источники вакансий

Сейчас поддержан **career.habr.com**: ссылка на вакансию и поиск по каталогу.
HTML отдаётся сервером, JavaScript не нужен, блокировок с сервера нет.
`robots.txt` Хабра разрешает `/vacancies` и запрещает `/responses` и личные разделы —
мы читаем только публичные страницы и ничего не отправляем от имени пользователя.
Между запросами пауза 1 секунда.

Ссылки на hh.ru не поддержаны намеренно: с сервера отдаётся 403, см. `docs/01-market.md`.
Для них по-прежнему текст или скриншот.

## Режимы прогона

`--steps` выбирает именованный режим, а не набор галочек. Цены и время — из
замера недели 0 (`docs/decisions.md`), они же показываются в вебе до запуска.

| Режим | Шаги | Цена | Время |
|---|---|---|---|
| `evaluate` | оценка | 0.17 ₽ | 13 с |
| `apply` | оценка + резюме + письмо | 0.64 ₽ | 40 с |
| `all` | плюс подготовка к интервью | 0.81 ₽ | 54 с |

Неизвестное имя режима падает на `evaluate`: опечатка не должна запускать
полный пакет. Режимы описаны в `probe/profiles.py` — в продукт переезжают оттуда.

Отдельно от режима: `--model deepseek-v4-pro` — сравнить Flash с сильной моделью.

## Куда класть данные

- `data/resumes/` — PDF, DOCX или TXT резюме.
- `data/vacancies/` — тексты вакансий, по файлу на вакансию.

Обе папки и `out/` в `.gitignore`: это персональные данные, в репозиторий не идут.
Резюме и вакансии для прогона держите в разных папках, иначе резюме попадёт
в пакетный прогон как вакансия.

## Что смотреть в результатах

1. **Разброс баллов.** Если все оценки в пределах 1.0 — промпт врёт и льстит.
   Сводка сама предупредит об этом.
2. **Evidence в требованиях.** Должны быть ссылки на конкретный опыт, не общие слова.
3. **Выдумки.** В `changes` тейлоринга и в STAR-историях не должно появляться
   опыта, которого нет в резюме. Это главный риск продукта.
4. **Цена и время** — в конце каждого прогона.
