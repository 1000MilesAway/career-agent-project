# career-agent

Веб-сервис, который помогает искать работу: собирает вакансии из десятка
источников, оценивает каждую против вашего резюме через LLM и готовит
материалы для отклика — тейлорнутое резюме, сопроводительное, подготовку
к интервью. Отклик отправляет сам пользователь: сервис принципиально не
автооткликается.

## Что умеет

- **Оценка вакансии по резюме** — балл 1–5 и вердикт (откликаться / с
  оговорками / не тратить время), разбор требований (что совпадает, чего не
  хватает, что критично), красные флаги, зарплатная оценка относительно рынка,
  вопросы работодателю.
- **Материалы под вакансию** — резюме, переупакованное под требования
  (одноколоночный ATS-читаемый PDF/DOCX), сопроводительное в трёх углах подачи,
  подготовка к интервью со STAR-историями из вашего опыта.
- **Общий пул вакансий** — посты из источников собираются в одну базу на всех,
  дедупликация, проверка живости, детект фейковых вакансий и мошенничества.
- **Трекер откликов** — статусы от «оценено» до «оффер», подсветка зависших,
  анализ паттерна после серии отказов.
- **Тарифы и лимиты** — бесплатный и Pro, лимиты расхода по дневному и
  недельному окну, оплата через Platega.

## Источники вакансий

hh.ru (через отдельный сервис-провайдер), Хабр Карьера, GeekJob,
Telegram-каналы и чаты (публичные и через юзербот-провайдер), сайты
работодателей и ATS — Сбер, Яндекс, VK, Huntflow, Greenhouse, Lever, Ashby,
плюс ссылки, добавленные пользователем вручную. Списки каналов, работодателей
и сигналов фрода — данные в `data/sources/`, а не код.

## Как устроено

```
Browser (React SPA) ──JSON/HTTPS──▶ FastAPI (REST) ──▶ Postgres
       ▲                                │                  ▲
       └──── polling статуса job ───────┤                  │
                                        └── enqueue ──▶ worker ──▶ DeepSeek API
```

Долгие LLM-операции (оценка 20–60 с) идут через очередь: SPA создаёт job,
опрашивает статус и рисует прогресс. Очередь — таблица `jobs` в Postgres и
воркер-процесс, без Redis.

| Путь | Что |
|---|---|
| `core/` | ядро пайплайна: промпты, фильтры, triage, шаги модели, источники, экспорт резюме. **Решает, но не хранит** — ничто в `core/` не импортирует `app/`, ядро тестируется без Postgres |
| `app/` | продукт: FastAPI + Postgres. Роутеры `app/api/`, связка ядра с БД `app/services/`, воркер `app/worker.py`, админ-CLI `app/cli.py` |
| `frontend/` | кабинет: React SPA (Vite, TypeScript), свой образ с nginx |
| `migrations/` | Alembic |
| `docs/` | спецификация, архитектура, роадмап, журнал решений (`decisions.md` + индекс), эксплуатация |

Принципы, которые держит код:

- **Правило подтверждений** — ничего сгенерированного не пишется в состояние
  без явного «да» пользователя (`core/proposals.py`).
- **LLM-вызовы** — JSON-режим с Pydantic-схемой, один ретрай при невалидном
  ответе; стабильный префикс промпта под кэш DeepSeek; каждый вызов логируется
  с моделью, токенами и стоимостью.
- **Вакансии — общий пул**: `postings` одна на всех, у пользователя личная
  строка `vacancies`; листинг, прочитанный недавно, из сети не запрашивается.

## Стек

Python 3.12 · FastAPI · SQLAlchemy 2 (async) + asyncpg · Postgres 16 ·
Alembic · React + Vite + TypeScript · DeepSeek (OpenAI-совместимый API) ·
WeasyPrint · Docker Compose · Caddy (TLS)

## Локальный запуск

Окружение — `uv`:

```bash
uv sync --group dev
cp .env.example .env   # DEEPSEEK_API_KEY для платных шагов; остальное опционально

uv run pytest                        # тесты: ключ API и Postgres не нужны
uv run ruff check .
uv run python -m app.cli calibrate --source golden   # скоринг без модели и БД

docker compose up -d && uv run alembic upgrade head  # Postgres 16 на :5433
uv run uvicorn app.main:app --reload                 # API на :8000
uv run python -m app.worker                          # воркер очереди
```

Фронтенд — из `frontend/`: `npm ci && npm run dev`.

Источники hh.ru и Telegram-чатов работают через внешние провайдеры
(`HH_PROVIDER_*`, `TG_PROVIDER_*` в `.env`); без них эти источники просто
выключены, остальное работает.
