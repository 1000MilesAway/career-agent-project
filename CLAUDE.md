**career-agent** — коммерческий SaaS для поиска работы на рынке РФ. Пайплайн взят
из open-source [career-ops](https://github.com/career-ops-hq/career-ops) (далее **CO**),
но продукт другой: веб-сервис по подписке, любые сферы, **без автооткликов** —
отклик всегда отправляет человек.

Локальная копия CO — `/home/vpn/career-ops`: эталон поведения, а не библиотека.
Когда решение спорное, сверяться с её кодом и `node scan.mjs --dry-run`.
Расходиться с CO можно, но осознанно и с записью в `docs/decisions.md`.

**Перед работой читай `docs/decisions-index.md`** — что решено и какие развилки
уже проверены и закрыты, по строке на решение. Переоткрывать их без запроса
пользователя нельзя. Журнал `docs/decisions.md` (3000+ строк) целиком не читать:
нужную запись найти грепом по заголовку из индекса. Новое решение — запись в конец
журнала и строка в индекс (`tests/test_decisions_index.py` проверяет).

## Инвариант пайплайна

**Дорогое — последним. Порядок ступеней ломать нельзя.**

```
сбор (API/превью, 0 ₽)
  → бесплатные фильтры (стоп-слова, специализация, грейд, вилка, 0 ₽)
    → история виденного (0 ₽)
      → triage: один дешёвый вызов на всю пачку (~0.01 ₽/вакансия)
        → полная оценка выживших (~0.17 ₽/вакансия)
          → артефакты отклика: резюме, письмо, интервью (~0.64 ₽)
```

1. **Ни один платный вызов не делается до бесплатных ступеней.** Иначе
   пользователь платит за мусор.
2. **Отсев никогда не молчит.** Выброшенная вакансия несёт причину одной строкой
   и остаётся видимой (приглушённой, под фильтром) — как `data/discard.log` в CO.
3. **Неполный ответ модели не достраивается.** Если пачечный вызов вернул меньше
   вердиктов, чем просили, пропуски идут в `missing` и показываются, а не
   доклеиваются как «skip». Тихо отсеять несуждённое — худший из возможных багов.

## Правило подтверждений

Агент **предлагает**, пользователь **принимает**. Ничего сгенерированного не
пишется в состояние без явного «да»: ни профиль поиска, ни стоп-списки, ни
резюме. Механизм — `core/proposals.py` (`current` / `proposed` / `rationale`,
дифф, статус); API принимает изменение только явным вызовом, молчание = отказ.
Поля, которых предложение не касается, не затираются.

## Чего не делать никогда

- **Автоотклик** — ни в каком виде, ни по просьбе пользователя: позиционирование
  и юридическая граница. При этом в лендинге и маркетинговых текстах об этом
  не твердить.
- Хранить чужие пароли от job-бордов.
- Читать Telegram через юзербот (Telethon) — только публичное превью `t.me/s/`.
  Чаты недоступны в принципе: у групп нет превью (302).
- Добавлять зависимости без просьбы пользователя.

hh.ru скрейпить **можно** (с 2026-10-01). С боевого сервера hh отвечает 403,
поэтому его читает отдельный провайдер `hh-scrapper` (`root@185.153.180.173:8090`,
свой репозиторий); листинг запрашивается не чаще раза в сутки.

## Архитектура

Три части, и две границы между ними не нарушать:

| Путь | Что |
|---|---|
| `core/` | ядро пайплайна: **решает, но не хранит**. Промпты, фильтры, triage, шаги модели, источники, экспорт резюме |
| `app/` | продукт: FastAPI + Postgres. Роутеры `app/api/`, связка ядра с БД `app/services/`, воркер очереди `app/worker.py`, админ-CLI `app/cli.py` |
| `frontend/` | кабинет: React SPA, свой образ с nginx; правила — `.claude/rules/frontend.md` |
| `migrations/` | Alembic |
| `docs/` | спецификация, архитектура, роадмап, `decisions.md`, `ops.md` |
| `data/` | персональные данные и списки-данные; в `.gitignore` |

1. **Ничто в `core/` не импортирует `app/`.** Ядро обязано вызываться без БД —
   иначе фильтры и промпты не проверить тестом без Postgres.
2. **`app/` не отдаёт HTML, только JSON.** Две реализации одного экрана — то,
   ради чего удалялось файловое демо `probe/`.

Неочевидное, что легко перепутать:

- `core/sources/apply_link.py` — где пользователь **откликается**;
  `core/sources/description_link.py` — где вакансия **описана**.
- `core/liveness.py` закрывает вакансию только по явному признаку, иначе
  «неизвестно».
- Вакансии — **общий пул**: `postings` одна на всех, у пользователя — личная
  строка `vacancies`. Листинг, прочитанный недавно, из сети не запрашивается;
  отсеянное не хранится, причина вычисляется (`GET /api/vacancies/screened`).
- Деньги показывает только `app/api/admin.py` (только `is_admin`). Пользователь
  денег не видит — лишь проценты лимитов и время сброса (подробно — `docs/ops.md`).
- Списки каналов, стоп-слов, запросов, работодателей — **данные** (`data/sources/`),
  а не код: устаревают тихо, обновление не должно означать правку модуля.

## Команды

Окружение — `uv`: системного `pip` на хосте нет.

```bash
uv sync --group dev                  # зависимости из uv.lock
uv run pytest                        # тесты; ключ API не нужен
uv run ruff check .                  # линтер (--fix — автоправка)
uv run python -m app.cli calibrate --source golden   # проверка скоринга без модели и БД
```

С Postgres (для `app/`):

```bash
docker compose up -d                 # Postgres 16 на порту 5433
uv run alembic upgrade head
uv run python -m app.cli user-add you@example.com   # пароль печатается один раз
uv run uvicorn app.main:app --reload # API на :8000, /docs — схема; после правки .py перезапускать
uv run python -m app.worker          # воркер очереди, отдельным процессом
```

- Без Postgres набор проходит, DB-тесты скипаются сами (`tests/dbmark.py`).
  Падение «потому что нет базы» — баг в тесте.
- `data/golden/` нет в git, поэтому в worktree и в CI тесты золотого набора
  скипаются — это нормально.
- Набор обязан проходить при пустом `DEEPSEEK_API_KEY`: секреты тестам задаёт
  `tests/conftest.py`, а не машина разработчика.

## Git и выкатка

**Работаем прямо в `main`**: без feature-веток и PR, если об этом не попросили.
Проект ведёт один человек, ревью делать некому. Worktree заводить только по
просьбе или для изоляции параллельной сессии; коммит всё равно уходит в `main`,
а worktree и его ветка сносятся в той же сессии — брошенные worktree уже
блокировали `git checkout main`.

1. **До работы — `git fetch origin` и сверка с `origin/main`.** Рабочее дерево
   может отставать на десятки коммитов; снапшот git-статуса этого не покажет.
2. **До пуша — `uv run pytest` и `uv run ruff check .`** (и проверки фронтенда,
   если он менялся). Красный CI на сервер не едет.
3. **После пуша — подтвердить выкатку по `revision`**: дождаться, пока
   `curl http://82.25.161.103:8000/api/health` вернёт sha запушенного коммита
   (~2 минуты). Живой сервис со старой ревизией — не подтверждение; не
   дождался — так и написать.

Сервер `82.25.161.103` — боевой и единственный, заходить **`ssh max@`**, не
`root` (отказ по ключу = не тот пользователь). Хосты из `~/.bash_history`
относятся к другому проекту. Всё остальное про сервер, CI, `~/deploy.sh`,
авторизацию, почту и лимиты — **`docs/ops.md`**, читать перед такой работой.

**Платные ручки** (сканы, оценки) против боевой базы дёргать только с явного
согласия пользователя: они тратят деньги.

## Конвенции

- Python 3.12, ruff (`line-length = 100`), pytest с `asyncio_mode = "auto"`.
- **Тексты для пользователя — по-русски; код, комментарии, коммиты — по-английски.**
- Комментарий объясняет **почему**. Проверенная развилка («так нельзя, потому
  что ломается вот это») стоит комментария и записи в `docs/decisions.md`.
- Внешние сервисы в тестах мокаются. **Живые вызовы LLM в тестах запрещены** —
  промпты проверяются снапшотами на записанных ответах (`tests/fixtures/`).
- Секреты только в `.env`, в репозитории — `.env.example`.
- **Адрес, пользователь, путь — проверять, а не вспоминать.** Записанное в
  памяти могло относиться к другому проекту. Признак промаха — отказ выглядит
  не как запрет, а как «не найдено» или «не тот ключ».

## Ключевые решения

Подробности и причины — `docs/decisions.md`.

- **LLM:** DeepSeek через OpenAI-совместимый API; модели `deepseek-flash`
  (рабочая) и `deepseek-v4-pro` (сравнение). Обёртка тонкая, модель — конфигом.
- **Источники:** career.habr.com (JSON API + страница), Telegram `t.me/s/`, hh.ru
  через провайдер, geekjob, сайты работодателей и ATS (JSON-LD JobPosting).
- **Вход:** email + пароль (регистрация с подтверждением почты или CLI-командой
  админа) или Telegram; первый вход через Telegram создаёт учётку. Оплаты нет.
- Telegram-бот и браузерное расширение отложены.
