# CLAUDE.md

Проект: **career-agent** — SaaS-ассистент для поиска работы на российском рынке.
Идея взята из open-source [career-ops](https://github.com/career-ops-hq/career-ops)
(AI-скоринг вакансий, тейлоринг резюме, подготовка к интервью, трекер), но:
- не self-hosted, а сервис с подпиской;
- не только IT, а любые сферы;
- вход через веб-кабинет;
- **без автооткликов** — сервис никогда не отправляет отклики за пользователя.

## Статус

**Спецификация + пробник.** Продуктового кода нет. В `probe/` лежит стенд проверки идеи
(CLI + одна веб-страница, см. `probe/README.md`): резюме и вакансия → отчёт с баллом,
плюс замер токенов и рублей на каждый вызов. Неделя 0 пройдена, результаты в `decisions.md`.
В продукт переезжают промпты (`probe/prompts.py`), фильтры (`probe/filters.py`),
провайдер Хабра (`probe/sources/habr_api.py`) и стартовый шаблон (`probe/defaults.py`).

**Главный принцип сканера (из career-ops):** сбор и фильтрация — бесплатные,
LLM подключается последней и только к выжившим. Порядок: собрать по API →
отсечь стоп-словами, специализацией, грейдом, вилкой → пропустить уже виденное →
оценить остаток. Ломать этот порядок нельзя, иначе пользователь платит за мусор.
Стартовые списки слов и запросов поставляем мы, пользователь их правит,
агент предлагает изменения — но ничего не пишется без подтверждения.

Решения лежат в `docs/`:

| Файл | Что внутри |
|---|---|
| `docs/01-market.md` | конкуренты (РФ и мир), ситуация с hh.ru API, позиционирование |
| `docs/02-product-spec.md` | MVP: сценарии, функции, что не входит, монетизация |
| `docs/03-architecture.md` | стек, компоненты, модель данных, LLM-пайплайн, схема отчёта |
| `docs/04-roadmap.md` | план по неделям, риски, открытые вопросы |
| `docs/decisions.md` | журнал принятых решений с датами и причинами |

Перед любой работой прочитай `docs/decisions.md` — там зафиксировано, что уже решено
и почему. Не переоткрывай закрытые вопросы без запроса пользователя.

## Ключевые решения (кратко)

- LLM: **DeepSeek V4.1 Flash** через OpenAI-совместимый API (`base_url` на DeepSeek).
  Обёртка над LLM тонкая, модель меняется конфигом.
- MVP = веб-кабинет (React SPA) + FastAPI-бэкенд. Telegram-бот и браузерное расширение отложены.
- Вход по email и паролю. Регистрации и почты в MVP нет — учётки заводит админ CLI-командой.
  Оплата тоже вне MVP: лимиты считаем и показываем, деньги берём после публичной регистрации.
- Вопрос доступа к API hh.ru **открыт** — пользователь пробует получить официальный доступ.
  Пока считаем, что вакансия приходит от пользователя (текст, скриншот, файл).
- Бэкенд: FastAPI + SQLAlchemy 2 async + asyncpg + Alembic + Postgres, docker compose.
  Фронтенд: React + Vite + TypeScript, отдельное приложение, собирается в статику.
  (Соседние проекты `~/develop/berezka-*` больше не референс, хотя стек частично совпадает.)

## Конвенции (когда появится код)

- Python 3.12, ruff (`line-length = 100`, `select = ["E","F","I","UP","B"]`), pytest с `asyncio_mode = "auto"`.
- Секреты только в `.env`, в репо — `.env.example`.
- Тексты для пользователя — на русском, код и комментарии — на английском.
- Фронтенд: TypeScript, ESLint + Prettier, без классовых компонентов.
- Внешние сервисы в тестах мокаются, живые вызовы LLM в тестах запрещены.
- На хосте нет системного `pip`-venv (нет `ensurepip`); установлен `uv` (`~/.local/bin/uv`) —
  окружение создавать через `uv venv` / `uv pip install`.

## Команды

Окружение — `uv` (системного `pip` на хосте нет). Все команды ниже выполнены
и проверены; непроверенное сюда не пишем.

```bash
uv sync --group dev                  # поставить зависимости из uv.lock
uv run pytest                        # тесты (74 шт., ключ API не нужен)
uv run ruff check .                  # линтер
uv run ruff check --fix .            # линтер с автоправкой
```

Пробник в CLI (`probe.run --help` покажет все подкоманды):

```bash
uv run python -m probe.run --help
uv run python -m probe.run cost      # сводка расходов, бесплатно
```

Команды ниже **тратят деньги** — каждая дёргает LLM. Цена за вакансию из
замера недели 0: `evaluate` 0.17 ₽, `apply` 0.64 ₽, `all` 0.81 ₽.

```bash
# сканер как в career-ops: бесплатные фильтры до модели (основной сценарий)
uv run python -m probe.run scan2 --resume data/resumes/cv.md --remote --limit 8

# одна вакансия по ссылке на Хабр Карьеру
uv run python -m probe.run url --resume data/resumes/cv.md --url <ссылка>

# одно резюме против одной вакансии / против папки вакансий
uv run python -m probe.run one   --resume data/resumes/cv.md --vacancy data/vacancies/v1.txt
uv run python -m probe.run batch --resume data/resumes/cv.md --vacancies data/vacancies
```

Веб-экран пробника (порт меняется через `PROBE_PORT`):

```bash
uv run python -m probe.web           # http://127.0.0.1:8010
```

## Работа с git

Удалёнка: `git@github.com:1000MilesAway/career-agent-project.git`. Ветка по умолчанию — `master`.

- **В `master` не пушить.** Ни агенту, ни хуку автокоммита. Транк двигается
  только через просмотренный merge или PR, решение принимает пользователь.
- Работа идёт в ветках `feat/*`, `fix/*`, `probe/*`. Пушить свою ветку можно
  без спроса — это резервная копия, а не публикация в транк.
- **Worktree только по просьбе пользователя.** Изолированный worktree
  отпочковывается от удалённой ветки и не видит незакоммиченных файлов
  основного каталога — так 12–14.09 работа раздвоилась на две расходящиеся копии.
  Если worktree всё же нужен, сначала убедиться, что в основном каталоге
  нет незакоммиченного, и только потом ветвиться.
- `docs/decisions.md` дописывается **снизу** и никогда не переписывается целиком:
  файл правят обе стороны, и перезапись затирает чужие записи.
- Что не коммитить: `data/`, `out/`, `.env`, `.venv/` — они в `.gitignore`,
  там персональные данные и ключи.
