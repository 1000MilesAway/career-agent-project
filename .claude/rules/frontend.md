# Кабинет (`frontend/`)

React SPA на Vite + TypeScript, свой образ с nginx, который же проксирует `/api`
на контейнер api. Нужен Node 22.

```bash
cd frontend
npm ci                  # зависимости из package-lock.json
npm run dev             # http://127.0.0.1:5173, /api проксируется на 8000 (другой — VITE_API_TARGET)
npm test                # тесты интерфейса, сети не требуют
npm run typecheck       # все три проекта TS, включая тесты
npm run lint            # oxlint
npm run build           # сборка в dist/ (в git не кладётся)
```

**Тесты и сборка типизируются раздельно.** `npm run build` собирает только
`tsconfig.app.json`, где тесты исключены: ошибка типов в тесте не должна валить
прод-сборку, а тестовые глобалы — протекать в код приложения. Поэтому после
правки тестов гонять `npm run typecheck`, а не только `build`.

## Конвенции

- TypeScript строгий, oxlint + Prettier, функциональные компоненты.
  Единственный класс — `ErrorBoundary`: у React нет хука для перехвата ошибок
  рендера.
- **Данные — через SWR по ключу `/api/state`, никаких `useEffect` с `fetch`**:
  один payload отвечает на вопрос «что показать», и мутация ревалидирует его
  одним вызовом.
- Состояние, выводимое из данных, считается на рендере, а не хранится вторым
  `useState`.
- **Тексты интерфейса — в компонентах, а не в словаре переводов.** Одного языка
  достаточно, а вынесенные строки заставляют читать два файла.
- Поясняющих подписей в UI не писать: ни подсказок под полями, ни лида под
  заголовком страницы. Объяснения — в код и `docs/decisions.md`.

## Где что

- `src/api/` — типы контракта, клиент с токеном, хуки SWR.
- `src/pages/` — страницы; `Admin*Page.tsx` — дашборд владельца
  (`/admin/users`, `/admin/funnel`, `/admin/spend`, `/admin/sources`).
- `src/landing/` — лендинг: разметка в `frontend/index.html`, здесь стили и
  смена слайдов.
- `nginx.conf` — отдача статики и прокси `/api`.

Боевой кабинет — собранный бандл: правка видна только после пересборки образа
контейнера `web` (то есть после деплоя).
