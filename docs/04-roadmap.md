# План и риски

## Итог MVP — 2026-10-01

**MVP собран и стоит на `career-helper.site`** (ревизия `b03674b`). Годится для
тестеров, но **не для открытой регистрации**, хотя регистрация по почте и через
Telegram уже включена: не закрыты блокеры ниже.

### Что вошло

- Пайплайн целиком: разбор резюме → бесплатные фильтры → triage → оценка →
  резюме под вакансию, письмо, подготовка к интервью. Порядок ступеней
  закреплён, отсев с причиной, `missing` видим.
- Источники: Habr Карьера, Telegram (`t.me/s/`), geekjob, сайты работодателей
  и ATS; дедуп между источниками, проверка живости, фильтр по IT-аккредитации.
  Скан — фоновая задача.
- Резюме: PDF / DOC / DOCX / RTF / текст, ручная правка разобранного, версии
  с откатом, выгрузка в PDF / DOCX / MD с конструктором стиля.
- Чат-помощник: предлагает правки профиля, пользователь принимает диффом.
- Трекер-воронка с переносом мышью, избранное, скрытие.
- Вход: email+пароль, регистрация с подтверждением почты (Resend), Telegram
  (OIDC). Онбординг-тур.
- Квоты по тарифам (день/неделя), пользователю — только доли, не деньги.
- Инфраструктура: CI → автодеплой с автооткатом, HTTPS через Caddy, `revision`
  в `/api/health`.

**Разошлось со спекой** (`02-product-spec.md` не обновлена): сканирование
источников и самостоятельная регистрация числились «не в MVP», а стали его
ядром; оценка вакансии, присланной пользователем, наоборот, не сделана.

### Блокеры открытой регистрации

- [ ] **Согласие на ПД не спрашивается.** `POST /api/auth/consent` есть,
      фронт его не вызывает, а диалог профиля обещает «спросят при загрузке
      резюме» (`ProfileDialog.tsx`). Экран при первом входе — со строкой, чего
      сервис не делает (не откликается за вас).
- [ ] **Удаление данных.** Удалить резюме (обнуление ПД, строки остаются) и
      удалить аккаунт / отозвать согласие (каскад). Решено 2026-09-22 в
      `decisions.md`, не реализовано.
- [ ] **Политика обработки ПД** — страница, ссылка со входа; уведомление РКН.
- [ ] **Бэкапы базы.** На сервере crontab пуст, есть только ручные снимки
      за 2026-09-20/21. Нужен регулярный `pg_dump` с хранением вне хоста.
- [ ] **Сброс пароля** — почта уже есть, регистрация открыта, а забывший
      пароль заперт.
- [ ] **Мониторинг** — сейчас только `/api/health`, об ошибках и падении
      воркера никто не узнаёт.

### Без этого MVP не проверяет свою гипотезу

- [ ] **Вакансия от пользователя: ссылка или текст** (скриншот — позже).
      Главный сценарий спеки; сейчас в продукт попадает только найденное
      источниками. `core/sources/habr.py` для одной вакансии уже есть, ручки нет.
- [ ] **Метрики**: активация (вход → первый отчёт), возврат за 7 дней.
- [ ] **Опрос после 5-й оценки** — «оценка была честной/полезной?».
- [ ] **10 тестеров из знакомых** — не набраны (или не записано).

### Долги качества

- [ ] Прогон на 20–30 вакансиях **не из IT** на 3–4 резюме — долг недели 0,
      а продукт заявлен для любых сфер.
- [ ] Качество отчёта по TG-вакансии на плоском тексте не замерено.
- [ ] Полный платный сценарий на живом ключе — прогнан ли целиком, не записано.
- [ ] Обновить `02-product-spec.md` под фактический MVP.

## Бэклог

- [ ] Подсветка «тишины» в трекере через 7 дней после «откликнулся» (спека, сценарий 4).
- [ ] Анализ отказов после 5+ отказов (спека, сценарий 4).
- [ ] Оценка вакансии по скриншоту (vision).
- [ ] Лендинг: сейчас аноним видит только экран входа (см. открытый вопрос
      «что показывать без входа»).
- [ ] **hh.ru как источник — со своего сервера-сборщика** (решение владельца
      2026-10-03: под hh нужен отдельный сервер, а не прокси с боевого). Общий
      пул вакансий (2026-10-03) делает это возможным: сборщик кладёт вакансии в
      `postings` один раз на всех, частота запросов к hh — под одним лимитом,
      а не на каждого пользователя. Боевой сервер hh не трогает.
      Запрет на скрейпинг снят 2026-10-01
      (`decisions.md`). Страница поиска `hh.ru/search/vacancy` отдаётся простому
      `curl` без JS: с машины разработчика (выход через Литву) — 200 и 40 карточек,
      заголовок по `data-qa="serp-item__title-text"`. С боевого сервера (Финляндия)
      — `451` от `ddos-guard`, режется IP хостинга, а не признаки бота. Анонимный
      `api.hh.ru` — 403. Что сделать:
      1. Сервер с адресом, который hh не режет (российский; проверить тем же
         `curl` до оплаты). Как он отдаёт вакансии в пул — открыто: прямая
         запись в базу по сети или ручка приёма на боевом API с ключом.
      2. `core/sources/hh.py`: выдача поиска → карточки, затем страница вакансии;
         смена разметки — громкий `MarkupChanged`, как у geekjob.
      3. Редкий сбор малыми пачками: при частых запросах ждать капчу и
         ограничение частоты даже с хорошего адреса; 429/капча — отступ, а не
         повтор подряд.
      4. Дедуп с зеркалами hh в Telegram-постах (`core/dedup.py`).

Из разбора после общего пула (2026-10-03), по порядку пользы:

- [ ] **Пересчёт выдачи при смене профиля поиска.** Сейчас строки, найденные
      под старый профиль, остаются до «Очистить». С пулом можно бесплатно
      прогнать `PreScreen` заново: подходящее добавить, неподходящее и
      нетронутое (без оценки, отбора, избранного) убрать. 0 ₽, без сети.
      Минус: строки исчезают без нажатия — показать, сколько убрано и почему.
- [ ] **Вилка числами в фильтре кабинета.** В `postings` уже есть
      `salary_from/to`, `currency`. Осталось: `/api/state` отдаёт числа из
      колонок вместо разбора `salary_text` на каждом запросе, а перенесённые
      миграцией вакансии (у них колонки пусты) заполнить из текста одним
      скриптом.
- [ ] **Чистка пула.** Удалять фоновой задачей вакансии без единой личной
      строки, закрытые или не виденные 60–90 дней. `text_fp` можно оставить
      для дедупа. Сейчас пул ~1–2 МБ — не срочно.
- [ ] **Кэш разбора вакансии моделью, общий на всех.** Выжимка требований и
      условий один раз на вакансию, следующие оценки читают её вместо полного
      текста. Только при первой покупке оценки, никогда заранее — иначе
      нарушится «дорогое последним». Сначала замер экономии на 5–10
      вакансиях, решение — по нему.
- [ ] **`max_age_days` в профиле поиска** заведено, но не читается нигде:
      подключить фильтр «не старше N дней» или удалить поле.
- [ ] **Вес `/api/state`.** Раньше 2 767 строк у одной учётки в одном ответе;
      после пула — сотни. Замерить и вернуться, только если снова вырастет.
- [ ] **Метка мошенничества** — бесплатный фильтр для объявлений вида «оплата
      за обучение», «300 тыс. без опыта», контакт только в личке без компании.
      Словари и правила без модели, как стоп-слова; помечает с причиной, не
      прячет. Больше всего пользы в Telegram.
- [ ] **Список отсеянного в кабинете.** `GET /api/vacancies/screened` есть,
      экрана нет: по решению 2026-10-02 отсеянное не показывается.
- [ ] **Обход лент ATS без скана пользователя.** Закрытие по пропаже из ленты
      (2026-10-03) срабатывает, только когда ленту кто-то читает сканом. Если
      сканов нет неделю, вакансия помечается «давно не проверялась», но не
      закрывается. Фоновое чтение лент раз в несколько часов это закроет.
