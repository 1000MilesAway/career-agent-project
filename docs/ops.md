# Эксплуатация: сервер, деплой, авторизация, почта, лимиты

Справочник вынесен из `CLAUDE.md` 2026-10-06, чтобы не грузить его в каждую
сессию. Читать, когда задача касается сервера, выкатки, CI, авторизации, почты
или лимитов расхода. Причины решений — в `docs/decisions.md`.

## Сервер

**`82.25.161.103`** — боевой и единственный сервер проекта. Обращаться к нему
для проверок можно. Хосты из `~/.bash_history` (`5.188.23.51`, `5.101.116.103`)
относятся к другому проекту — не путать.

**Заходить `ssh max@82.25.161.103`** — пользователь `max`, не `root`. Под
`root` сервер отвечает `Permission denied (publickey)`, и это легко принять за
«доступа нет». Отказ по ключу означает неверного пользователя, а не запрет.

```bash
curl http://82.25.161.103:8000/api/health       # жив ли сервис, база и какая ревизия
curl http://82.25.161.103:8000/openapi.json     # схема API
ssh max@82.25.161.103 'cd ~/career-agent && git rev-parse --short HEAD'
ssh max@82.25.161.103 'docker ps --format "{{.Names}}\t{{.Status}}"'
```

Что где на хосте: `~/career-agent` — репозиторий (туда распаковывается bundle),
`~/deploy.sh` — скрипт выкатки **вне git**, `~/career-agent/.env` — секреты,
контейнеры `career-agent-{api,worker,web,edge,db}-1`.

**Домен — `https://gethire.ru`** (с 2026-10-08; до того `career-helper.site`,
его заблокировали). Регистратор и DNS — Reg.ru: A-записи `@` и `www` →
`82.25.161.103` напрямую. HTTPS держит контейнер `edge` (Caddy, `Caddyfile` в
корне), сертификат Let's Encrypt продлевается сам. Если DNS переедет в
Cloudflare — только «DNS only», без прокси.

**Порты.** Кабинет — 80/443 через `edge`: `http://82.25.161.103/` отдаёт SPA,
а `/api/` nginx проксирует на контейнер api, чтобы браузер оставался на одном
origin. API напрямую — порт 8000, `/api/health` там остаётся для проверки
выкатки снаружи.

`revision` в ответе health — короткий sha развёрнутого коммита; `unknown`
означает «стек подняли руками». **`GIT_SHA` не класть в `.env`**: `environment`
в compose перебивает `env_file` только когда переменная задана в окружении,
иначе подставится старое значение из файла и health будет вечно показывать
чужую ревизию.

**Кабинет в продакшене — собранный бандл.** Правка `frontend/` видна только
после пересборки образа; F5 на боевом кабинете старую сборку не обновит.

## CI и деплой

Настроено 2026-09-21.

```
коммит в main  →  CI (тесты + ruff + миграции)  →  зелёный  →  деплой на 82.25.161.103
                                                →  красный  →  на сервер НЕ едет
```

| Что | Где |
|---|---|
| Тесты, линтер, миграции | `.github/workflows/ci.yml` |
| Выкатка | `.github/workflows/deploy.yml` |
| Что делает выкатку на хосте | `~/deploy.sh` на сервере, **не в репозитории** |

Откат автоматический: сборка упала или `/api/health` молчит 60 с —
`deploy.sh` возвращает предыдущую ревизию и поднимает её. Снимок состояния до
пайплайна — коммит `11ce666` в репозитории на сервере.

Три урока, которые уже стоили сломанного пайплайна:

1. **Триггер деплоя — `push`, не `workflow_run`.** Последний читает своё
   определение из дефолтной ветки репозитория, и пока ею был не `main`, деплой
   молча не запускался вовсе — ни ошибки, ни прогона.
2. **Тесты не должны зависеть от того, чего нет в git.** `.env` и `data/` в
   `.gitignore`; набор, зелёный локально, падал в CI 27 ошибками. Секреты
   тестам задаёт `tests/conftest.py`. Проверка: набор обязан проходить при
   пустом `DEEPSEEK_API_KEY`.
3. **Версию экшена искать в списке ТЕГОВ**, а не релизов
   (`git ls-remote --tags`): у `setup-uv` релизы дошли до 10.x, а плавающие
   мажорные теги кончаются на `v7`, и прогон упал на несуществующем `v10`.

## Правки `~/deploy.sh` на хосте

Скрипт вне репозитория: его правка не покрыта ни тестами, ни ревью —
единственная страховка тут порядок действий:

1. **Бэкап до правки**: `cp ~/deploy.sh ~/deploy.sh.bak-$(date +%Y%m%d)`.
2. **Посмотреть файл целиком перед заменой.** Шаблон, написанный по памяти,
   промахивается: `git checkout --force "$PREVIOUS"` встречается в скрипте
   трижды, а не дважды — третий случай это выход при пропавшем `.env`, где
   стек не поднимается.
3. **Проверить синтаксис**: `bash -n ~/deploy.sh` и `diff` с бэкапом.
4. **Проверить результат выкаткой**, а не чтением: пуш в `main` и `curl`
   `/api/health`, пока `revision` не сменится.

Выдавать себе права на запись к хосту нельзя — правило в настройках добавляет
пользователь. Если классификатор блокирует действие, сказать об этом и
остановиться, а не искать обход.

## Авторизация

Без авторизации открыты только:

- `/api/health`, `/openapi.json`;
- `/api/auth/telegram` — `GET`: client_id и nonce для кнопки; `POST` с
  `id_token`: вход (незнакомый Telegram заводит учётку без email и пароля);
- `/api/auth/signup` — `GET`: включена ли регистрация, `POST`: завести учётку
  и отправить письмо;
- `/api/auth/verify` — ссылка из письма → токен;
- `/api/auth/password-reset` (письмо со ссылкой) и
  `/api/auth/password-reset/confirm` (токен из ссылки + новый пароль → токен входа);
- `/api/artifacts/kinds`, `/api/vacancies/statuses`.

Остальное — под JWT: `POST /api/auth/login` с email и паролем учётки с
подтверждённой почтой или `POST /api/auth/telegram`.

`SECRET_KEY` обязателен: на значении по умолчанию приложение откажется
стартовать — предсказуемый ключ позволяет подписать токен любому.

## Почта

**Resend** (`RESEND_API_KEY`, `MAIL_FROM` в `.env`; без любого из них
регистрация по почте выключена). Бесплатный тариф — 100 писем в сутки на весь
сервис; отправитель обязан быть на подтверждённом в Resend домене, иначе письма
доходят только до владельца аккаунта Resend. В тестах `send_email` мокается.

## Лимиты расхода

С 2026-10-01 расход ограничен лимитами по тарифу, дневным и недельным. Лимиты —
в долларах себестоимости по цене вне пика: `FREE_DAY_USD`, `FREE_WEEK_USD`,
`PAID_DAY_USD`, `PAID_WEEK_USD` (0 — окно выключено). День сбрасывается в
00:00 МСК, неделя — в понедельник в 00:00 МСК; перерасход переносится в
следующий период.

- Учёт — `users.quota_*`, проверка — `spend.ensure_can_spend` на входе каждого
  платного шага, исчерпанный лимит отвечает 402.
- Тариф — `users.paid_until`, выдаётся `app.cli user-plan EMAIL --days 30`.
  Админ лимитов не имеет.
- Каждый вызов модели пишется строкой в `llm_calls` (`spend.charge`); владелец
  видит траты в кабинете: «Админка» → «Траты».
- Рубли (`spent_rub`, `cost_rub`) — учёт владельца. **Пользователь денег не
  видит** — ни рублей, ни долларов: только проценты окон и время сброса.
